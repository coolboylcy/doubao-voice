# Doubao Voice 商业化方案

状态：第一版方案，已与当前代码的边界对齐。

## 产品定位

Doubao Voice 是一个 macOS 全局语音输入工具：用户按住右 Option 说话，文字直接进入当前 App。产品价值不是“又一个录音软件”，而是把语音变成任何输入框里的最快输入方式。

商业版的核心体验应当是：安装简单、权限引导清楚、录音状态一眼可懂、订阅状态透明、识别失败可恢复。

## UI 方向

当前 HUD 已改为深色、低干扰的胶囊样式：

- 菜单栏使用单色符号，不再使用跨字体表现不稳定的 emoji。
- 录音时显示实时波形和“剩余时间”，不再显示正向计时。
- 剩余 10 秒时进入橙红警告态：边框、时间和提示文字一起高亮，显示“即将自动结束 · 还剩 N 秒”。
- 最后 10 秒不再让中间识别文本覆盖安全提示。
- 录音结束后切换成独立的“识别中”，避免用户误以为仍在录音。

建议后续增加一个完整的设置/账户窗口，包含四个区域：

1. 账户：登录邮箱、订阅状态、到期日、管理订阅。
2. 用量：本周期已用时长、剩余时长、最近同步时间。
3. 录音：热键、最长单次录音、语言、麦克风选择。
4. 隐私：是否允许诊断数据、音频是否保存、数据发送目的地。

## 订阅和额度

### 推荐的第一版商业规则

- 未登录或订阅过期：不能开始录音。
- 新用户可有一次短期试用，试用时长由服务端配置。
- 每个订阅周期有一个“可识别分钟数”配额；配额不是本地写死，而是服务端下发。
- 录音开始前检查订阅有效期和剩余额度。
- 录音中按实际采音时长扣减；剩余不足一次完整录音时，按剩余时长限制本次录音。
- 剩余 10 秒时沿用 HUD 警告态；额度耗尽后自动停止录音，保留已说内容并尝试完成识别。
- 断网时允许短时间离线宽限，但不能无限期离线使用。建议默认 24 小时，之后必须重新同步授权。

“本地计算一个 used_seconds，然后永远相信本地文件”不适合作为商业授权机制，用户可以改系统时间或删除文件。客户端只能保存缓存，最终授权和周期额度必须由服务端签发和校验。

### 推荐的授权链路

```text
用户点击订阅
  → 托管 Checkout 完成付款
  → 支付平台 webhook 通知授权服务
  → 授权服务签发短期 entitlement
  → App 校验签名并缓存
  → daemon 每次 start 前检查
  → 录音过程中按剩余额度自动停止
```

授权对象至少包含：`account_id`、`plan_id`、`status`、`period_start`、`period_end`、`quota_seconds`、`used_seconds`、`offline_grace_until` 和 `token_expires_at`。

客户端只内置公钥，服务端用私钥签发授权。不要把支付平台 secret、豆包长期 access key 或授权签名私钥放进客户端。

## 支付渠道决策

### 第一阶段：官网订阅 + Paddle 托管收款

建议首发选择“官网直接下载 + Paddle Checkout + Paddle Customer Portal”：

- 当前项目需要麦克风、辅助功能和输入监控权限，直接分发更容易保留现有能力。
- Paddle 的 Customer Portal 已覆盖发票、付款方式、订阅取消和订阅管理，减少自建账单系统的工作量。
- 付款完成后通过 webhook 更新自己的授权服务，App 不直接相信浏览器跳转成功页面。

如果产品主要面向中国大陆用户，需要在正式选型前确认收款主体、地区可用性、发票和人民币支付方案；必要时可以把 Paddle 替换为国内合规支付服务，但授权服务的接口保持不变。

### 第二阶段：Mac App Store + StoreKit

如果更看重“一键安装、系统自动更新和 Apple 账户购买”，可以改走 Mac App Store + StoreKit 自动续订。但当前的全局热键、辅助功能和输入监控路径需要先做原生 macOS 权限验证，不能直接假设把现有 Hammerspoon 方案塞进 App Store 就能通过审核。

## 安装包和进程形态

### 短期可发布形态

可以先将当前项目做成经过签名和公证的 `.app` + `.dmg`：

- 用户拖拽一个 App 到 Applications。
- 首次启动显示权限向导。
- App 负责安装/升级后台 helper 和 launchd 配置。
- 用户只看到一个菜单栏 App，helper 在后台运行，不要求用户理解 Python、uv、Hammerspoon 或 socket。

这能快速发布，但底层仍然有 Hammerspoon + Python helper 两个进程，属于“用户看上去是一个 App”，不是“技术上只有一个进程”。

### 正式商业版形态

建议逐步迁移为原生 Swift/SwiftUI + AppKit：

- 一个原生菜单栏 App 管理热键、录音、HUD、权限和账户。
- 音频采集改用 `AVAudioEngine`。
- 全局热键和文字注入由原生 App 处理。
- ASR 协议和授权客户端嵌入 App；必要时只保留一个隐藏 helper 做崩溃隔离。
- 删除 Hammerspoon、uv 和用户手工编辑 JSON 的依赖。

这样才能真正做到“下载后双击安装、只认识一个 App”。但它是一次产品化重构，不建议为了赶首版而用脚本把现有依赖强行打包。

## 必须补齐的商业化事项

- 用 macOS Keychain 保存登录凭证和短期授权，不再让用户手工把长期密钥写进 JSON。
- 云端 ASR 不应让每个客户端长期持有你的火山引擎密钥；应由你的服务端签发短期 token 或代理请求。
- 首次启动做权限分步引导：麦克风、辅助功能、输入监控，并提供“重新检查”按钮。
- 明确隐私承诺：默认不保存原始音频，识别完成后立即丢弃；日志不得包含音频和识别全文。
- 提供退款、取消订阅、恢复订阅、换机登录和客服入口。
- 增加自动更新、版本回滚和崩溃保护；正式分发必须 Developer ID 签名并 notarize。
- arm64 和 Intel 分开验证；本地 FunASR 只作为 Apple Silicon 能力，不要让 Intel 用户误以为可用。
- 对授权、额度、断网、系统时间回拨、重复启动、睡眠唤醒和杀掉 helper 做自动化测试。

## 实施顺序

1. 当前代码：完成 HUD 倒计时和商业版视觉基线。
2. 授权服务：账户、订阅 webhook、签名 entitlement、额度账本。
3. 客户端：账户窗口、订阅墙、授权缓存、额度检查和自动停录。
4. 打包：隐藏现有运行时依赖，生成签名公证 DMG。
5. 原生化：SwiftUI/AppKit 替换 Hammerspoon，形成真正单 App 体验。
