# 语音对话（跟 Claude Code 说话）设计

日期：2026-09-04
状态：已实现，待真人验收

前身是[听写设计](2026-09-04-doubao-voice-input-design.md)。听写做完后用户指出真正想要的是对话——「我说一句，他说一句，甚至可以打断」——而不是语音输入法。两者最终并存，各占一个 Option 键。

## 1. 为什么不用「豆包端到端实时语音大模型」

火山控制台里有现成的端到端实时语音大模型，speech-to-speech，原生支持打断，就是豆包 App 那个对话模式的底层。但它**是个黑盒：自己听、自己想、自己答，中间那步让不出来**。它不能读你的文件、跑你的测试、改你的代码。

用户要的是「跟 Claude Code 对话」——说一句，它真去干活。这必须把「思考」这一步换成 Claude，所以只能拼：

```
语音 → ASR → Claude Code → 文本 → TTS → 语音
```

代价是失去原生打断和端到端低延迟，收益是它真能干活。ASR 那一半复用听写already有的实现。

## 2. 核心矛盾与解法

**对话要即时应答，但 Claude 干活要几十秒。** 读十个文件、跑个测试是常态。做成「你说完 → 干等 30 秒 → 它开口」，体验比打字还差。

解法是 `claude -p --output-format stream-json`：输出流式出来，它一说话就念一段。于是变成「你说完 → 马上『好，我看一下』→ 边干边报进展 → 最后念结论」。

这是整个设计的支点。没有流式，这个功能不值得做。

## 3. 流里什么能念

实测 `stream-json` 的消息类型（`--verbose` 才出全）：

| 消息 | 处理 |
|---|---|
| `assistant.content[].text` | **念** |
| `assistant.content[].thinking` | 跳过 |
| `assistant.content[].tool_use` | 压成一句提示（"看 config.py"），给 HUD 和提示音，不念全文 |
| `user.content[].tool_result` | **绝对不念**——整个文件内容都在里面 |
| `result` | 本轮结束，带 `session_id` / `total_cost_usd` / `duration_ms` |
| `system` (init / hook_*) / `rate_limit_event` | 丢弃 |

## 4. 口播过滤（`speech.py`）

Claude 的回复是写给眼睛看的，原样念出来是灾难。两道防线：

**源头**——`--append-system-prompt` 告诉它「你在通过语音对话，用口语短句，不要输出代码块和表格，长内容写进文件后只说写好了」。

**兜底**——`to_speech()` 处理漏网的：

| 输入 | 念成 |
|---|---|
| 围栏代码块 | 删掉，末尾补「代码我写好了」 |
| Markdown 表格 | 「这里有个表格」 |
| URL | 「一个链接」 |
| `/Users/a/b/c/foo.py` | `foo.py` |
| `` `x` `` / `**x**` / `## x` | `x` / `x` / `x。` |
| 超过 4 项的列表 | 念前 4 项 +「等 12 项」 |

纯函数，17 条测试。这层直接决定体验好坏，所以单独成层。

## 5. 打断语义：只停嘴，不停手

按一下左 Option 打断时，Claude 可能正在跑 `npm test`。**打断只 kill 掉 TTS 播放进程，那轮继续跑完，输出丢弃。**

理由有二：中途砍掉命令执行或文件写入会留下烂摊子；而且人打断多半是想补一句话，不是想撤销。

已在 `test_interrupt_stops_speaking_only` 里显式断言「打断后那轮任务仍未结束」。

## 6. 工作目录跟随前台终端

你在哪个项目下，说话就在哪个项目里干活。实现：

```
osascript 拿 Terminal 前台 tab 的 tty
  → ps -t <tty> 找带 + 的前台进程组
  → lsof -a -p <pid> -d cwd 读 cwd
```

前台不是 Terminal（比如在浏览器里说话）时回退到 `~`。跳过 `caffeinate`/`lsof`/`ps`/`osascript` 这些不代表用户位置的进程。

## 7. 成本

每轮对话是一次 `claude -p`。实测（Sonnet）：

| | 花费 |
|---|---|
| 新会话第一轮（载入项目上下文） | ~$0.31 |
| `--resume` 之后每轮 | ~$0.02 |

**差 14 倍。** 所以 `session_id` 必须在 daemon 侧延续，不能每句话新开。默认模型定为 sonnet——探测时用默认模型跑一次简单的「读文件说一句话」花了 $0.47，对话场景绝大多数是短指令，不值这个价。

## 8. 交互

| 操作 | 行为 |
|---|---|
| 按住左 Option | 开录，HUD 显示波形 |
| 松手 | 识别 → Claude 干活 → 边干边念 |
| 它说话/干活时按一下左 Option | 打断（只停嘴） |
| 录音中按 Esc | 丢掉这一句 |
| 按住不放满 `max_recording_seconds` | 自动结束，防键卡住烧额度 |
| 菜单栏「重开一段对话」 | 清空 `session_id` |

菜单栏图标：🎙 待命 / 🔴 听写中 / 💬 在听你说 / 🤔 在干活 / 🚫 daemon 掉线。

## 9. 组件

| 文件 | 职责 |
|---|---|
| `speech.py` | 输出转口播 + 工具调用摘要（纯函数） |
| `agent.py` | 驱动 `claude -p`，流切成 Speech/Action/Done/Failed |
| `tts.py` | `say` 播放队列，可掐断。接口为换豆包语音合成留 |
| `frontcwd.py` | 前台终端 cwd |
| `daemon.py` | 加 chat_start/stop/interrupt/reset 四命令与 chat_* 事件 |
| `lua/init.lua` | 左 Option 分派、打断、Esc、录音上限 |

TTS 放在 daemon 侧而不是 Lua 侧，因为它要和 Claude 的流式输出严格对齐——念完一段才念下一段。

## 10. 已知限制与待办

- **TTS 是系统 `say`**，声音机械。链路验证完可换豆包语音合成（同一控制台，也有免费试用）。`Speaker` 的接口就是为这次替换留的。
- **打断只能按键**，不能声控。声控要处理回声（扬声器的声音被麦克风采到会自己打断自己），得戴耳机或做回声消除。
- **左 Option 可能误触**——如果用它打特殊字符的频率高，会莫名开始录音。真有问题就改成双击触发。
- **daemon 重启后 `session_id` 丢失**，下一轮变成新会话（贵 14 倍）。可以持久化到文件，但重启本来就不频繁，暂不做。
- **没有并发保护**：上一轮还在念时按住左 Option 会打断并开新一轮，但上一轮的 Claude 进程仍在跑，两轮的输出可能交叉。实际使用中很少遇到，遇到了再加队列。
