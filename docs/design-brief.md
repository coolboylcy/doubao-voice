1. **品牌规范** —— 一份能约束后续所有设计的文档

## 二、产品是什么（这些是硬事实，不要编，也不要夸大）

**语音狗子**（英文 Voice Doggo）是一个 macOS 全局语音输入工具。

按住右 Option 键说话，松手，识别出的文字直接出现在当前光标处。任何 App 都能用：
代码编辑器、终端、聊天窗口、浏览器输入框。

关键事实：

- 识别**全程在本机完成**。不联网、不要账号、不要 API Key、完全免费
- 模型随 App 携带（FunASR SenseVoice），所以安装包约 250 MB
- 要求 Apple Silicon Mac、macOS 13 以上
- 首次启动约 10 秒预热识别引擎，之后即按即用
- 单次录音上限 2 分钟
- 开源，MIT 协议，代码在 https://github.com/coolboylcy/voice-doggo

完整交互只有三个动作：

| 动作 | 结果 |
|---|---|
| 按住右 Option 说话，松手 | 文字上屏 |
| 短按右 Option | 进入持续录音，再按一下结束 |
| 录音中按 Esc | 取消，什么都不上屏 |

不要发明产品没有的功能。没有云同步、没有账号体系、没有团队版、没有 AI 助手对话。

## 三、品牌故事（这是灵魂，不要弄丢，也不要放大）

这个工具是**开发者做给女朋友的**。

女朋友的昵称叫「小狗子」。她在做 vibe coding——用 AI 写代码，需要不停打字描述需求、
解释想法、纠正 AI，手很累。所以他做了这个，让她可以直接说话。

「语音狗子」这个名字就是这么来的。

**这决定了它不是一个效率工具的口吻。** 不谈"提升 300% 输入效率"，不堆技术名词，
不用科技公司那种冷感。它是一份礼物，语气应该是日常的、温的、带一点笨拙的可爱——
像一只趴在旁边等你开口的小狗。

**但不要腻。** 不要通篇撒糖，不要把故事讲成朋友圈文案。克制地讲一次，讲清楚就够了，
剩下的让产品本身说话。

对外故事的标准版本（96 字，可直接用）：

> 「语音狗子」是开发者做给女朋友的。她叫小狗子，用 AI 写代码时要不停解释需求，打字很累。
> 他希望她一开口，字就落在光标处。这只狗于是被做出来：在本机听懂话，不联网，不登记，
> 不收费。它不是效率指标，只是一句顺手说出口的话。

## 四、已经定下来的东西（请在此基础上做，不要推翻）

### 4.1 色彩

| 角色 | 色值 | 用途 |
|---|---|---|
| 暖黑 | `#241F1B` | 主文字与结构。不要用纯黑 `#000000` |
| 奶油米 | `#EADCC5` | 底色、卡片、吉祥物本体 |
| 苔绿 | `#536B5A` | **只**给下载按钮、录音状态、明确可点击的元素 |
| 砖红 | `#A44A3E` | 取消与错误 |

深色模式：强调色变浅（苔绿 → `#8FAE97`），背景不要纯黑，保持暖灰。

苔绿不是常见科技色，也不像警告色。它更像安静存在的信号：在听、可以按、正在识别。
整体要"温"但不能甜，"可爱"但不能幼稚，"礼物感"但不能朋友圈化。

### 4.2 语气正反例

| 不这么说 | 这么说 |
|---|---|
| 一键唤醒 AI 语音引擎，重塑输入体验 | 按住右 Option，说完松手，字就出现 |
| 极速启动，秒级响应 | 首次启动约 10 秒，让它把模型摆好 |
| 全场景智能语音助手，效率提升 300% | 编辑器、终端、聊天框、浏览器输入框都能用 |
| 端到端低延迟本地推理架构 | 识别在你本机完成，不联网 |
| 小狗子爱你，快下载吧！ | 它一开始就是做给小狗子的 |

承认边界，不回避：要授权、要等预热、有时长上限、不是云服务。

### 4.3 字体

不引入外部字体（见技术约束）。用系统字体栈：

- 中文标题：衬线体 `"Songti SC","STSong"` —— 已验证在 macOS 上效果好
- 中文正文：`system-ui, "PingFang SC"`
- 技术事实（`250 MB`、`10s`、`Esc`）：等宽 `ui-monospace, SFMono-Regular, Menlo`
- 手写点缀（如"为小狗子而生"）：`"Hanzipen SC","Hannotate SC"`

## 六、交付物 2：吉祥物 IP

### 现状与方向

吉祥物就叫「狗子」，昵称「小狗子」。性格：温、笨、可靠、不主动打扰。
像趴在桌边等一句话的小狗，不抢镜头，不表演。

**重要：目前存在两套并行的视觉，需要你收敛成一套完整体系。**

- 一套是 **3D 黏土摆件**（奶油米色、垂耳、圆眼、深色小鼻头、正面端坐）——已用于 App 图标
- 一套是 **实景照片 + 手绘线稿**——已用于官网

两套混用会让品牌涣散。请决定主视觉走哪条路（或如何分工），并给出明确规则：
什么场合用哪一种。

### 需要的状态变体

至少四个，对应产品的真实时刻：

| 状态 | 用在哪 |
|---|---|
| 待命 | 菜单栏空闲、官网主视觉 |
| 在听 | 录音中的浮层与菜单栏 |
| 想 | 识别中 |
| 送到 | 文字上屏的瞬间 |

**关键要求：表面呆，内心有货。** 让人感觉这只狗其实什么都懂，只是懒得表现。
神态差异主要靠眼睛，不要靠夸张的肢体动作。

**状态之间必须是同一只狗。** 之前生成的一组变体在这一点上失败了——眼睛画法各不相同
（细眯眼 / 带高光圆眼 / 带睫毛 / 带眉毛），四张放在一起不像同一个角色。请先定死五官
画法，再做表情差异。

### 素材交付格式

- 主形象：2048×2048，透明背景
- 各状态：同上，风格一致
- 极简剪影版：用于 16px 的场景，只保留最少特征（详见第八节）

## 七、交付物 3：官网

单页，用于介绍和下载。

### 内容结构（可调整，但这些信息都要有）

1. 顶栏：Logo、导航、下载按钮
2. Hero：主张 + 下载 + 运行要求
3. 品牌故事
4. 三步怎么用（按住 → 说 → 松手，**这里的编号是成立的，因为确实有先后**）
5. 本地运行的几条事实（不联网、不登记、到处能用、首次预热、免费）
6. 尾部：再次下载 + 品牌信息
7. 页脚

### 硬性约束

- **单个 HTML 文件，完全自包含**：CSS/JS 内联，图片用 data URI，不引用任何外部资源
  （没有 CDN、没有 Google Fonts、没有外链图片）。因为要能直接丢在任何地方托管
- 深色与浅色都要好看，跟随 `prefers-color-scheme`
- 手机上正常显示
- 不要任何追踪、统计、cookie
- 主行动只有一个：下载。不要轮播、不要滚动秀、不要 FAQ 手风琴、不要社交图标墙
- 键盘可访问，focus 可见，尊重 `prefers-reduced-motion`

下载指向 `https://github.com/coolboylcy/voice-doggo/releases`。

现有一版在 `web/index.html`，可以作为起点或推倒重来。

## 八、交付物 4：App 内 UI（最容易被忽略，请务必做）

这是用户每天真正看到的部分。当前状态和要求如下。

### 8.1 App 图标

macOS 规范：

- 1024×1024 画布，图标本体占 **824×824**，四周透明留白
- 圆角是 **squircle（超椭圆）**，不是普通圆角矩形，用普通圆角一眼能看出区别
- 需要 16/32/64/128/256/512/1024 全套

**16px 和 32px 必须单独设计，不能拿大图缩。** 这是已经踩过的坑：精细图稿缩到 32px 时
细节全部粘连成色块，16px 更是什么都看不出。小尺寸只放得下轮廓，请单独画简化版。

现状：图标已换成吉祥物，但小尺寸用的是临时画的狗头剪影，质量一般，需要重做。

### 8.2 菜单栏状态图标

macOS 菜单栏的特殊约束：

- 尺寸约 **16–18pt**，必须是**模板图像**（单色，由系统按深浅色自动反色）
- 需要四个状态：空闲 / 录音中 / 识别中 / 出错
- 录音中会额外着色（红），出错着橙，所以形状本身必须在单色下就能区分状态

**这个尺寸下画不了狗的细节。** 建议用最简特征（比如耳朵轮廓）或抽象符号，
但要和整体品牌有明确关联。

另外提醒一个真实存在的问题：MacBook 刘海屏上，菜单栏图标多了会被排进刘海下面导致
完全看不见。这不是设计能解决的，但图标本身要足够有辨识度，用户才能在一排图标里找到它。

### 8.3 录音浮层（HUD）

录音时屏幕底部出现的深色胶囊浮层。当前包含：

- 左侧呼吸红点
- 中间实时波形（40 格 × 50ms = 2 秒可见历史，从右往左滚）
- 右侧剩余时间倒计时
- 波形下方单独一行显示识别中的文本
- 最后 10 秒转橙红警告态

**两条规则是踩坑换来的，改的时候不要破坏：**

1. **录音期间波形不能消失。** 早先让识别文本顶掉波形，说得稍长波形就永久消失，
   看着像死机——其实还在录。所以文字必须单独占一行，跟波形共存
2. **波形按真实音频时间轴推进，不按渲染帧推进。** 每收到一个电平压入一格。
   早先每帧压一格加平滑，等于把波形变成了"音量趋势图"，既有延迟又不对应实际说话

可以重新设计视觉，但这两条行为约束要保留。吉祥物是否出现在这里、以什么状态出现，
由你决定。

### 8.4 设置页

当前有四块：快捷键说明、权限状态（麦克风/辅助功能/输入监控）、识别服务说明、启动行为。

**要求按极简原则重新审视：装完就能用的东西不该占据界面。**

- 权限引导是必需的（三项权限缺一不可，且用户必须手动授权）
- 快捷键说明对新用户有价值
- 其余能砍则砍

注意：这个 App 是菜单栏常驻应用（`LSUIElement`），没有主窗口，设置页是按需弹出的
独立窗口。它不是"主界面"，不要按主界面的规格去设计。

## 九、技术约束汇总

| 约束 | 原因 |
|---|---|
| 官网必须单文件自包含 | 要能直接丢任何地方托管，且不依赖外部服务 |
| 不引入外部字体 | 同上；也避免首屏字体闪烁 |
| App 图标 16/32px 单独设计 | 缩放必糊，已验证 |
| 菜单栏图标必须是模板图像 | 否则深浅色切换时会瞎 |
| 深浅色都要成立 | macOS 用户切换很常见 |

## 十、验收标准

- 官网在浅色和深色、桌面和手机四种组合下都截图检查过
- App 图标在 16/32/64/128/256 各尺寸下分别检查过，不是只看大图
- 菜单栏图标在浅色和深色菜单栏下都检查过
- 吉祥物各状态放在一起看，是同一只狗
- 所有文案对照第 4.2 节的语气正反例检查过一遍
- 没有任何地方出现产品不具备的功能
